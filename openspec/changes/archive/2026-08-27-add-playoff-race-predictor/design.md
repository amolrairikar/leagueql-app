## Context

See proposal.md — Why. The Playoff Bracket page (`frontend/src/features/playoff_bracket/playoff-bracket.tsx`)
reaches an empty state (`matches.length === 0`) whenever `PLAYOFF_BRACKET#{season}` returns nothing, which is
exactly the mid-regular-season state we want to fill. Relevant existing facts:

- Matchups carry team display fields, scores, `week`, `playoff_tier_type`, and `playoff_round`. Unplayed games
  persist as `0-0` placeholders, detected by `isUnplayedMatchup` (`frontend/src/lib/matchups.ts`). Regular vs
  playoff is a per-matchup label; there is no stored playoff-team count or regular-season length exposed to the
  client.
- The Sleeper/ESPN league-settings blobs (with playoff-team count and regular-season length) are already
  fetched into S3 by the onboarder, but the processor drops them (ESPN) or reads `playoff_week_start` only as a
  transient value (Sleeper). Nothing durable stores them.
- Demo mode serves committed fixtures from `frontend/src/lib/demo-data.json` (generated by
  `scripts/utility_scripts/seed_demo_data.py`) via `queryDemoLeague`; every demo season is fully completed
  (10 teams, 15 regular weeks, 4 playoff teams, a real bracket, zero unplayed games).

## Goals / Non-Goals

**Goals:**
- Fill the in-progress empty state with the locked predictor UI, computing the projection entirely client-side.
- Persist the minimal league settings the cutoff/boundary need, reusing the existing precomputed-view + query
  pattern.
- Let demo mode showcase the predictor without a live in-progress season.

**Non-Goals:**
- No score projection — picks have no points; points-for stays season-to-date and is only a tiebreaker.
- No new fetching from the platforms (the raw settings are already in S3).
- No predictor/toggle on real completed seasons (toggle is demo-only, per the user).
- No infrastructure/architecture change.

## Decisions

- **Compute the projection from `MATCHUPS` alone.** Records, points-for, and team display (name, logo, owner)
  all derive from the matchups already fetched, so the predictor needs no standings fetch and the `live` and
  `replay` modes share one code path. Alternative (fetch `SEASON_STANDINGS` for baseline) was rejected because
  it only gives the *final* standings for a completed season, so it can't serve the demo replay's "as of week
  N" baseline.
- **New `LEAGUE_SETTINGS#{season}` precomputed view + `LEAGUE_SETTINGS` queryType** (over extending METADATA or
  `GET /leagues/{id}`). Consistent with every other view; the frontend reads it through the existing
  `queryLeague` path. Extraction lives in the processor (`src/processor/handler.py`) where the settings blobs
  are already parsed per season — Sleeper in the pre-pass loop, ESPN in the settings branch — because the
  onboarder writes METADATA before those blobs are parsed. Persisted as a small per-season item (no DuckDB
  transform); wire a new `EntityType` + key schema.
- **Default `num_playoff_teams` to 6 when the platform omits it**, and surface an "assumed" note by the cutoff
  line so the UI never silently shows a wrong line. `playoff_week_start` reuses the processor's existing
  default (15 for season ≥ 2021 else 14).
- **Predictor modes.** `live` = the empty-state branch for the latest in-progress season; pickable set =
  unplayed regular-season weeks bounded by `regular_season_weeks`; the component self-gates (renders the tool
  only when ≥1 pickable week and no played playoff matchup, else the existing empty message). `replay` = demo
  toggle over a completed season; pickable set = the last 3 regular-season weeks presented unpicked, baseline =
  tally of played regular-season matchups before that window.
- **Demo toggle is the one `isDemoMode()` branch** in `playoff-bracket.tsx`, shown only when a bracket exists.
  The demo seed emits `LEAGUE_SETTINGS` rows and `demo-api.ts` maps the new queryType, so the predictor's data
  path is otherwise identical to production.
- **Reuse over duplication.** Export the currently-private `isRegularSeason` from
  `compute-schedule-swap.ts` and reuse its W/L/T tally + `formatRecord`; reuse `isUnplayedMatchup`,
  `avatarColor`, `SeasonSelect`, `TeamAvatar`.

## Risks / Trade-offs

- **Future playoff-week placeholders can be labeled `NONE`** (Sleeper labels them regular-season until a
  bracket exists) → bound the pickable set by `regular_season_weeks` from `LEAGUE_SETTINGS`, not by the
  per-matchup label alone.
- **`num_playoff_teams` unknown for some historical/edge leagues** → default to 6 and label the cutoff as
  assumed; the predictor stays functional.
- **Regenerating `demo-data.json` changes a large committed fixture** → the only intended diff is the added
  `LEAGUE_SETTINGS` buckets (deterministic `SEED = 42`); review the diff to confirm nothing else moved, and
  update any demo-data shape assertions.
- **Adding a new `EntityType`/queryType touches several backend spots** (enum, key schema, SK map, OpenAPI
  enum, DynamoDB spec) → covered explicitly in tasks so none is missed.
