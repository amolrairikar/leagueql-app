# BE-022: AI Weekly Matchup Recap

## Description
Generates an **AI-written weekly recap column** for each completed week of a league's matchups —
medium-long, lighthearted-but-journalistic prose with roasts where warranted — from the existing
precomputed matchup highlights, and caches it in DynamoDB as a `MATCHUP_RECAP#{season}#WEEK#{week}`
item. The frontend ([FE-037](../frontend/FE-037-weekly-matchup-recap.md)) reads the cached text
through the existing query API ([BE-005](BE-005-query-precomputed-views-api.md)); generation never
happens on the request path.

This is the repo's first **AWS Bedrock / LLM** integration. Recaps are generated by a dedicated
**recap-generator Fargate task** (`src/recap_generator/handler.py`, container entrypoint `main()`)
that calls **Meta Llama 3.3 70B Instruct** on Bedrock via the boto3 `bedrock-runtime` **Converse**
API. It runs as a **Fargate task rather than a Lambda** because a full multi-season backfill, paced
under the model's low Bedrock requests-per-minute quota, can exceed the 15-minute Lambda cap; a task
has no such limit. Because Converse is model-agnostic, the model is parameterized by the
`BEDROCK_MODEL_ID` env var. Llama 3.3 70B is **inference-profile-only**, so this is the US
cross-region inference profile ID `us.meta.llama3-3-70b-instruct-v1:0` — invoking the bare
foundation-model ID `meta.llama3-3-70b-instruct-v1:0` with on-demand throughput fails ("Retry with
the ID or ARN of an inference profile"). Swapping to any other Converse-capable Bedrock model is a
one-line change with no code change.

The task **backfills every season and every completed week** the league has, generating
**sequentially** with request starts spaced under the model's RPM quota (see throttling below). It is
**idempotent**: any `(season, week)` that already has a recap is skipped, so re-runs are cheap and
safe.

## Scope
- **Bedrock helper — `src/common/bedrock.py`** (vendored into the recap task image). A module-level
  `boto3.client("bedrock-runtime", config=_retry_config)` using **adaptive** retry mode with a
  raised `max_attempts` (10) — adaptive mode's client-side token-bucket rate limiter slows the
  request rate on a `ThrottlingException`, and the extra attempts let each call ride out the backoff
  rather than failing fast. Exposes `generate_recap(highlights: dict) -> dict` which
  calls `client.converse(modelId=<BEDROCK_MODEL_ID>, system=[{text: voice}], messages=[…],
  inferenceConfig={"maxTokens": 2000})` and parses the response into `{"headline", "body"}` (body =
  `\n\n`-joined paragraphs, no markdown).
  - **Voice (system prompt):** lighthearted-but-journalistic column, roasts where deserved, a single
    headline line then body paragraphs. The headline is explicitly steered to be **creative** —
    wit/wordplay/vivid imagery hooked to the week's most dramatic real moment, with generic
    "Week N recap" / "A beats B" templates banned (cleverness must still come from real events, never
    invented facts).
  - **Name / fact-fidelity guardrail (required in the system prompt):** use the team and
    manager/display names **exactly as provided** and **never invent real names or facts** not
    present in the highlights — no fabricated surnames from usernames (`chris_j` stays
    "Chris" / "chris_j", never "Chris Johnson"), no invented stats, injuries, or events. Every
    number, player, and outcome must trace to the input. Stating an obvious deduction from the data
    (e.g. the two Semifinal winners meet in the Finals) is allowed.
- **Recap-generator Fargate task — `src/recap_generator/handler.py`** (east-only, on the shared
  `leagueql` ECS cluster; Bedrock lives in `us-east-1`). Containerized via `src/recap_generator/Dockerfile`
  (build context `./src`, vendoring `common/`); `CMD ["python", "handler.py"]` runs `main()`:
  - **Input via container env overrides** (set by the trigger's `run_task` call): `CANONICAL_LEAGUE_ID`
    (required), `PLATFORM`, `NATIVE_LEAGUE_ID`, `CORRELATION_ID`, `TRACE_CONTEXT` (JSON W3C carrier).
    `main()` assembles the event dict and runs `_handle`.
  - No-op when billing is disabled (`is_billing_enabled()` off).
  - **Server-side premium gate:** read the `METADATA` item; when the premium feature is paywalled
    (`is_feature_paywalled("premium_feature")`) and the league is **not** active
    (`now >= subscription_end_time`, or absent), log and `return` — **no Bedrock spend**. The
    active-subscription comparison mirrors `require_active_subscription`
    ([BE-014](BE-014-subscription-access-control.md)).
  - **Enumerate all seasons** via the GSI1 `LEAGUE_LOOKUP` lookup (merging season sets, same logic
    as the API's `get_league_seasons`) — **every** season, not just the latest.
  - **Per season, enumerate completed weeks** by prefix-querying `MATCHUPS#{season}#` (presence
    implies completion — there is no in-progress flag). Read `STANDINGS#{season}` once per season for
    records/context.
  - **Idempotent skip:** drop any `(season, week)` that already has a
    `MATCHUP_RECAP#{season}#WEEK#{week:02d}` item (batch-read existing recap SKs per season).
  - **Build highlights** per matchup (both teams' display name + record + score, winner/margin, each
    side's top 1–2 starters and top bench from the `starters`/`bench` `PlayerStat` lists, playoff
    round if any); trim PlayerStat detail to keep input tokens low.
  - **Generate sequentially at a paced rate:** loop over the remaining pairs, each calling
    `generate_recap(...)` after a thread-safe rate limiter. Concurrency does **not** help — a single
    model's Bedrock RPM quota is the ceiling and each Converse call is faster than the required
    spacing, so the rate cap (not call latency) is the bottleneck; parallel calls would only burst and
    throttle. The control is the **request pace**: `RECAP_MIN_REQUEST_INTERVAL_SECONDS` (default 10s)
    spaces out request starts to stay under the RPM quota (floor `60/RPM` — an 8-RPM model needs
    >= 7.5s). Tune it: raise if still throttling, lower after a quota increase. Per-week failures are
    caught and logged so one failure never aborts the batch. The Fargate task has no time cap, so even
    a full multi-season backfill runs to completion at this pace.
  - **Store** one item per generated week: `PK=LEAGUE#{canonical_league_id}`,
    `SK=MATCHUP_RECAP#{season}#WEEK#{week:02d}`,
    `data={headline, body, generated_at, model}`.
- **Tracing ([BE-021](BE-021-async-chain-otel-propagation.md)):** the task calls
  `init_tracing("leagueql-recap-generator")` at module top level and `main()` wraps the run in
  `traced_handler("recap_generator.handle", carrier=<TRACE_CONTEXT env, JSON-decoded>)`, so it
  **continues** the upstream trace — the processor's `processor.handle` span on the live-refresh
  trigger and the webhook's `stripe_webhook.handle` span on the activation trigger — falling back to a
  fresh root span when no carrier is present. A true no-op when Axiom is unconfigured. Requires the
  five `opentelemetry-*` packages (+ `boto3`, `openfeature-sdk`) in
  `src/recap_generator/requirements.txt`.
- **Triggers (two; both launch the same task via the shared `common.recap_task.run_recap_task`
  helper → `ecs:RunTask`, both premium-gated + idempotent):**
  - **Trigger A — subscription activation** ([BE-015](BE-015-stripe-billing.md)): the Stripe webhook
    fire-and-forget launches the task when `record_active_subscription(...) == True` → immediate full
    backfill for the newly-premium league.
  - **Trigger B — processor completion** ([BE-004](BE-004-data-processing-pipeline.md)): the
    processor fire-and-forget launches the task at the end of every onboard/refresh → fills any
    missing weeks (the just-completed week). No-ops for non-premium leagues and skips already-recapped
    weeks. `run_recap_task` passes the per-league input as container env overrides and is a no-op when
    the `RECAP_TASK_*` env is unset (e.g. the non-east region); a failed `RunTask` is swallowed so the
    caller never fails.
- **Query API:** `MATCHUP_RECAP` is added to the `QueryType` enum and `QUERY_TYPE_TO_SK_BASE` in
  `src/api/main.py`; no route changes — `query_league` already prefix-queries by SK base and gates on
  league membership. Read-path premium gating stays client-side (`SubscriptionGuard`), consistent
  with the other analytics/Weekly-Awards features; recaps simply do not exist for non-subscribers.
- **Infra:** an **ECS Fargate task definition** `recap_generator` (east-only, on the shared `leagueql`
  cluster, 512 CPU / 1024 MB) with the container env (`DYNAMODB_TABLE_NAME`, `BEDROCK_MODEL_ID`,
  `RECAP_MIN_REQUEST_INTERVAL_SECONDS`, feature-flag + Axiom SSM params), a CloudWatch log group, and
  an **ECS task-failed** EventBridge rule → SNS alert (prod). An **ECR repo** `leagueql-recap-generator`
  (+ lifecycle policy) holds the image. A **task role** (`recap-generator-task-role`, trust `ecs-tasks`)
  carries DynamoDB read/write + GSI1, the `bedrock:InvokeModel` grant scoped to the Llama 3.3 70B
  foundation-model + inference-profile ARNs, `aws-marketplace:Subscribe`/`ViewSubscriptions`
  (self-subscribe), and feature-flag + Axiom SSM read; a separate **task execution role**
  (`recap-generator-task-exec-role`) pulls the image from ECR and writes task logs. The `stripe_webhook`
  and `processor` Lambdas get `RECAP_TASK_{CLUSTER,DEFINITION,CONTAINER,SUBNETS,SECURITY_GROUPS}` env
  (the webhook's are `""` in the non-east region) and `ecs:RunTask` + `iam:PassRole` (on the task +
  exec roles) on their roles, replacing the prior `lambda:InvokeFunction`. The image is built + pushed
  to ECR by `.github/workflows/build.yaml` (content-addressed tag → `recap_image_tag` TF var), not the
  Lambda-zip path. **Bedrock model access:** the Bedrock *Model access* console page is retired —
  access to Bedrock models (Anthropic, Meta, etc.) is now an **AWS Marketplace subscription** on the
  account. Rather than a manual console grant, the task role carries
  `aws-marketplace:Subscribe`/`ViewSubscriptions` so its **first run self-subscribes** the account to
  the Llama 3.3 70B Bedrock Marketplace product (account-wide, one-time; subsequent runs just use
  `bedrock:InvokeModel`). Until that first subscribe settles (~2 min), Converse returns an
  `AccessDeniedException` citing the Marketplace actions. (Alternative, if you'd rather not grant the
  role subscribe rights: have an admin subscribe the account once via AWS Marketplace, then drop those
  two actions.)

## Edge Cases
- **Non-premium league:** the server-side gate returns before any Bedrock call, so trigger B is a
  cheap no-op for every non-subscriber. (Trigger A only fires on a real activation.)
- **Billing disabled (BE-017):** `is_billing_enabled()` off → the task no-ops immediately and
  nothing is generated; matches the read-path behavior where recaps are ungated when billing is off
  but also never generated by these triggers in that state.
- **No matchup data for a league/season:** the work list is empty → nothing generated, no error.
- **Already-recapped week:** skipped via the idempotent existence check; re-runs (both triggers) only
  generate still-missing weeks. A recap is **never** regenerated once written.
- **Bedrock failure / throttle on one week:** the request-pacing rate limiter
  (`RECAP_MIN_REQUEST_INTERVAL_SECONDS`, sized to the model's RPM) plus adaptive retry (client-side
  rate limiter + raised `max_attempts`) keep the batch under the model's quota; a call that still
  exhausts retries is caught and logged so the batch continues and writes every other week. The
  missing week is regenerated by the next trigger (idempotent skip leaves it on the work list). If
  throttling is persistent, raise `RECAP_MIN_REQUEST_INTERVAL_SECONDS` and/or request a Bedrock
  service-quota increase for the model. **Note:** for Llama 3.3 70B the binding limit is RPM (8),
  not TPM (600K) — pace by `60/RPM`.
- **Renewal / re-refresh re-trigger:** safe — both triggers re-run the same idempotent enumeration;
  only genuinely-missing weeks cost Bedrock spend.
- **No invocation time cap:** the Fargate task runs to completion, so even a full multi-season backfill
  paced under a low RPM quota (which could exceed the 15-min Lambda limit — the reason for the task)
  finishes in one run. A task that fails hard fires the ECS task-failed alarm; idempotency makes the
  next trigger refill any unwritten weeks.
- **Fire-and-forget launch failure:** `run_recap_task` wraps `RunTask` in try/except, so a failed
  launch never fails the webhook (still 200) or the processor run.
- **Tracing unconfigured:** `init_tracing`/`traced_handler` are no-ops; the task runs untraced with
  `correlation_id`-only logging. An Axiom export error never changes the outcome.

## Acceptance Criteria
- [ ] For a **multi-season premium** league, a task run writes a `MATCHUP_RECAP#{season}#WEEK#{week}`
      item for **every** completed week of **every** season, each with a non-empty `headline` and
      `body` plus `generated_at` and `model`.
- [ ] A second run for the same league is a **no-op** (no new Bedrock calls, no item changes).
- [ ] A **non-premium** league (paywalled + no active subscription) produces **no** items and makes
      **no** Bedrock call.
- [ ] With billing disabled, the task no-ops immediately.
- [ ] One week's Bedrock failure does not abort the batch — every other week is written.
- [ ] The Stripe webhook launches the recap task **only** when `record_active_subscription` returns
      `True`; a stale/duplicate event does not.
- [ ] The processor launches the recap task at the end of every onboard/refresh; a failed launch does
      not fail the processor run.
- [ ] `GET /leagues/{leagueId}/query?queryType=MATCHUP_RECAP#{season}#WEEK#{week}` returns the cached
      recap for members and 404s for a missing week.
- [ ] Recaps use team/manager names exactly as provided and contain no fabricated names, stats, or
      events not present in the highlights.
- [ ] With Axiom configured, a live-refresh run produces a `recap_generator.handle` span **as a
      child of** `processor.handle`, and a Stripe activation produces a `stripe_webhook.handle` root
      trace with `recap_generator.handle` as its child; both degrade to a clean no-op when Axiom is
      unconfigured.
